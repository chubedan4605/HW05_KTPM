Continuous Performance Testing — Pipeline phát hiện hồi quy p95
Mô hình đề xuất cho EShop: theo dõi commit → quyết định → thực thi → phân tích → chặn hồi quy

1THEO DÕI (Watch)

GitHub WebhookSự kiện push / pull_request trên repo EShop (backend, frontend, infra)
Phân tích thay đổiDiff các file: backend/*.js, database.js, Dockerfile, dependency (package.json)
Chấm điểm rủi roRisk score = trọng số file × lịch sử hồi quy; query mới = rủi ro cao

2QUYẾT ĐỊNH (Decide)

Chỉ tài liệu / READMEBỏ qua — không chạy performance test
Rủi ro thấp (frontend, CSS)Chạy smoke test hiệu năng (2 phút, 10 VU E2E)
Rủi ro cao (API, DB, SQL, dependency)Chạy full suite: Load + Stress + Spike (kịch bản HW05)
Ngân sách: tối đa 6 full-run/ngày Hàng đợi: merge queue tuần tự Cache Docker image + node_modules

3THỰC THI (Execute)

Runner chuyên dụngMáy ảo GitHub Actions self-hosted, cấu hình cố định (đã pin CPU/RAM) — chuẩn hoá môi trường
Deploy SUT isolationDocker: backend + SQLite re-seed mỗi lần chạy, dữ liệu CSV như HW05 (users.csv, products.csv)
Kịch bản JMeter/k6Test plan {StudentID}_{Scenario} tái sử dụng từ repo; monitor tài nguyên (node_exporter) chạy song song

4PHÂN TÍCH (Analyse)

Trích chỉ số p95 / p99 / RPS / err%Từ raw .jtl (script analyze_jtl) theo từng endpoint
So với baseline + dải dung saiHồi quy khi p95 > baseline × 1,10 VÀ vượt khoảng tin cậy 95% của 5 lần chạy chuẩn hoá
Chống nhiễuNghi ngờ → chạy lại tối đa 2 lần; kết luận theo đa số (2/3) để giảm false alarm

5PHẢN HỒI & CHẶN (Report & Gate)

Đạt / tốt hơn baselineGreen check trên PR; cập nhật perf-baseline.json (commit bot)
Xác nhận hồi quy p95Chặn merge (required check) + mở GitHub Issue kèm biểu đồ so sánh + tag tác giả commit
Dashboard & lịch sửLưu kết quả vào artifact / Grafana; xu hướng p95 theo từng bản release

Đánh đổi cần cân nhắc (Trade-offs)

Chi phí CIFull suite tốn 20–25 phút runner/lần + máy chuyên dụng chạy 24/7. Giảm bằng tầng quyết định (chỉ ~15% commit chạm backend) và smoke test 2 phút cho phần còn lại.
Báo động saiNhiễu từ shared runner, cold cache, dữ liệu khác nhau. Giảm bằng cấu hình pin, dải dung sai 10%, khoảng tin cậy 95% và chính sách chạy lại 2/3 — đổi lại phát hiện hồi quy chậm hơn vài phút.
Baseline lỗi thờiTuning có chủ đích (WAL, cache) làm baseline cũ thành "quá dễ". Cho phép cập nhật baseline qua PR riêng có review, không tự động sau mỗi lần đạt.
Độ trễ phát hiệnChỉ phát hiện hồi quy khi có commit; không thay thế chaos/soak định kỳ — vẫn cần soak 15 phút hàng tuần trên nhánh main.
